# Committed sample run

Everything in this folder was produced by:

```bash
python -m src.pipeline --sample --out data/sample_run
```

## This is synthetic data

The input was generated by [`../../src/sample.py`](../../src/sample.py) from random
distributions. Agency and vendor names are fabricated and prefixed `SYNTHETIC`.

Nothing here is a finding about the District of Columbia, its agencies, or any real
vendor. The run is committed for one reason: so that the pipeline's outputs can be
reviewed in a browser without installing or executing anything.

The generator deliberately injects a few structured behaviours — repeated amounts just
under a review threshold, same-day vendor bursts, and one rapidly concentrating vendor
relationship — so the scoring engine has something to rank. Those rows carry no label and
the engine is given no hint that they exist, so the run demonstrates the mechanism rather
than proving accuracy. No accuracy claim is made or possible without validated outcomes.

## What is and isn't committed

Two artifacts the pipeline writes are **not** committed, to keep the repository small:

| Not committed | Why it is safe to omit |
|---|---|
| `raw_purchase_card.csv` (6,160 rows) | Regenerated exactly from `src/sample.py` at seed 7 |
| `processed_ranked_exceptions.csv` (all 6,160 scored rows) | The 185 rows above the recommended threshold are committed instead |

Run the command above to write the full set locally. `tests/test_sample.py` asserts that a
fresh run reproduces the committed queue byte-for-byte, so the committed extract cannot
silently drift from the code.
